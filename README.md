# AIOps & Development: End-to-End ML Deployment

An academic end-to-end project covering a Kaggle dataset, model training in Jupyter/Colab, model serialization, FastAPI, Docker, GitHub, and GitHub Actions CI.

> **Important:** This is an educational classification demo, not a medical diagnostic tool.

## Dataset (Task 1)

Kaggle: [Breast Cancer Wisconsin (Diagnostic) Data Set](https://www.kaggle.com/datasets/uciml/breast-cancer-wisconsin-data)

Download `data.csv` from Kaggle and put it in the project root, next to `train_model.ipynb`. The CSV should contain `diagnosis`, the 30 numerical measurement columns, and usually `id` plus `Unnamed: 32`. The notebook removes non-feature columns.

## Task 2 & 3: Train in Jupyter or Colab

1. Open `train_model.ipynb` in Jupyter Notebook or upload it to Google Colab.
2. Upload/place `data.csv` beside the notebook.
3. Run all cells from top to bottom.
4. Check the evaluation metrics.
5. The notebook creates `model.joblib` and `feature_names.json` in the project root.
6. Copy those two files into the local VS Code project root if you trained in Colab.
7. Commit the artifacts to your GitHub repository so Docker and CI can load the trained model.

The notebook uses a stratified 80/20 train-test split and a Random Forest classifier. The reported test metrics are from the held-out test set; do not describe them as guaranteed real-world performance.

## Task 4: Run FastAPI in VS Code (without Docker first)

Use Python 3.11. From the project root in VS Code terminal:

### Windows PowerShell

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
uvicorn app.main:app --reload
```

If PowerShell blocks activation, use Command Prompt and run `.venv\\Scripts\\activate.bat`.

Open:
- API docs: http://127.0.0.1:8000/docs
- Health check: http://127.0.0.1:8000/health

### Test `/predict`

Use `/docs`, open `POST /predict`, click **Try it out**. The request must include all feature names from `feature_names.json`; the API intentionally rejects missing or extra feature names.

A safe way to prepare a complete test request in the VS Code terminal is:

```powershell
python -c "import json; f=json.load(open('feature_names.json')); print(json.dumps({'features':{k:1.0 for k in f}}, indent=2))"
```

Copy the generated JSON into Swagger's request body. These synthetic values test that the endpoint works; they are not a meaningful medical sample.

## Task 5: Execute through Docker

Install and start Docker Desktop first. Ensure the model files exist before building.

```powershell
docker build -t breast-cancer-api .
docker run --name breast-cancer-container -p 8000:8000 breast-cancer-api
```

Visit http://localhost:8000/docs and test the API. In a second terminal:

```powershell
docker ps
docker logs breast-cancer-container
```

Stop and remove the container:

```powershell
docker stop breast-cancer-container
docker rm breast-cancer-container
```

If port 8000 is already in use, map another host port, for example `-p 8001:8000`, then open `http://localhost:8001/docs`.

## Task 6: Create GitHub repository

Create an empty repository on GitHub named `aiops-ml-deployment`. Do not add a README on GitHub if you already have this local README.

```powershell
git init
git add .
git commit -m "Build end-to-end ML deployment project"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/aiops-ml-deployment.git
git push -u origin main
```

Replace `YOUR-USERNAME` with your GitHub username. Confirm `model.joblib` and `feature_names.json` are committed; they are required by the Docker image and CI workflow.

## Task 7 & 8: GitHub Actions CI

The workflow is at `.github/workflows/ci.yml`. GitHub Actions automatically:
1. Checks out your repository.
2. Installs Python dependencies.
3. Confirms model artifacts exist.
4. Runs the FastAPI tests with pytest.
5. Builds the Docker image.

After pushing, open your GitHub repository → **Actions** → **ML API CI**. A green check means the workflow completed successfully. If it fails, open the run and inspect the failed step's log.

## Common errors

- **`Model artifacts missing`**: run all cells in `train_model.ipynb` and put both generated files in the project root.
- **`FileNotFoundError: data.csv`**: download the Kaggle CSV and place it beside the notebook.
- **PowerShell script execution disabled**: activate the environment from Command Prompt instead, or adjust the policy only if permitted on your machine.
- **Docker cannot connect**: start Docker Desktop and wait until its engine is running.
- **GitHub Actions says model artifacts missing**: check that `model.joblib` and `feature_names.json` were committed and pushed.
- **422 from `/predict`**: include all and only the feature names in `feature_names.json`.
